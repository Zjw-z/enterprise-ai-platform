# 可观测性与运维指南

## 结构化日志

生产配置使用`log_format: json`。每条日志至少包含时间、等级、Logger和消息；
HTTP请求期间自动包含`request_id`。平台接受合法`X-Request-ID`或自动生成，
响应头和审计记录返回同一标识，便于从网关一路关联到Runtime和审计。

## Prometheus 指标

平台默认通过 `GET /metrics` 暴露真实运行指标：

- `eap_http_requests_total`：按请求方法、路由模板、状态码统计；
- `eap_http_request_duration_seconds`：HTTP 延迟分布；
- `eap_runtime_tasks_total`：Agent Runtime 的完成、失败、超时和取消数；
- `eap_runtime_task_duration_seconds`：Runtime 成功任务延迟；
- `eap_tool_calls_total`：Tool 成功与失败数；
- `eap_tool_call_duration_seconds`：Tool 调用延迟；
- `eap_http_requests_active`：当前正在处理的 HTTP 请求数。

指标只使用路由模板和注册组件名，不使用用户 ID、任务 ID 等高基数字段。
Runtime 与 Tool 指标直接消费 EventBus 的真实执行事件，并非前端模拟数据。

```yaml
metrics_enabled: true
metrics_path: /metrics
observability_service_name: enterprise-ai-platform
```

## OpenTelemetry

平台支持向 OTLP/HTTP Collector 发送 HTTP Span，默认关闭：

```yaml
otel_enabled: false
otel_exporter_otlp_endpoint: null
otel_trace_sample_ratio: 0.1
```

生产环境配置示例：

```yaml
otel_enabled: true
otel_exporter_otlp_endpoint: http://otel-collector:4318/v1/traces
otel_trace_sample_ratio: 0.1
```

`0.1` 表示采样约 10% 的请求。HTTP Span 记录 method、route 和 status，
不记录完整请求内容与用户敏感信息。

## 探针

- `GET /health/live`：进程存活探针；
- `GET /health/ready`：数据库、Milvus 等关键依赖就绪探针；
- `GET /metrics`：Prometheus 抓取端点。

生产编排系统只应在 readiness 成功后接入业务流量。
