# 案例三：Agent 自主规划与选择 Tool

本案例仍使用 `agents/multi_tool_trip_agent`，重点不是“调用多个 Tool”，而是理解决策权。

## 职责划分

- 开发者：定义业务目标、Tool Schema、授权范围、最大迭代次数和安全策略。
- LLM：根据当前问题决定直接回答还是调用哪些 Tool，以及下一轮做什么。
- AgentToolRound：解释结构化 ToolCall 并控制每轮执行。
- ToolExecutor：执行确定性的授权、参数、审批、超时、重试、幂等和熔断。
- Runtime：记录全过程，不参与业务规划。

## Prompt 应该怎么写

Prompt 应表达“结果必须满足什么”和“哪些事情禁止做”，不要写成：

```text
第一步调用天气，第二步调用景点，第三步调用预算。
```

应写成：

```text
根据用户目标判断是否需要外部信息；需要时选择合适工具。
不得编造工具结果。信息不足时说明假设，最终给出可执行旅行方案。
```

## 如何验证自主规划

分别输入：

1. “你好”——应允许不调用 Tool。
2. “杭州有哪些景点”——通常只需景点 Tool。
3. “两人杭州三日舒适游，结合天气给预算”——通常需要多个 Tool。

通过任务 Trace 对比三次 `llm.call` 与 `tool.call`，即可看到模型如何按问题动态选择。
若业务步骤必须百分之百执行，请改用 Workflow，不要依赖概率性的 LLM 规划。
